## 2026-10-06 14:55 — New frontmatter fields, Professional Profile section, PDF visual fix, central tab

### New frontmatter keys
- `phone:` — renders as a `tel:` link in the contact row (independent of the legacy `contact_phone:`).
- `location:` — renders as a plain text item in the contact row.
- `languages:` — accepts a comma- or semicolon-separated list and renders as a small-caps line under the contact row.

### Professional Profile section
- A markdown `## Professional Profile` section is now recognised. Its free-form prose renders as justified paragraphs in a new `<section class="cv-profile">` block — no `cv-section-head`, no entry/tag structure.
- The parser pulls the section out of the normal section list and returns it as `ResumeData.profile`. Bullets inside the section become their own paragraph; consecutive lines form a single paragraph (double newline = paragraph break).

### PDF export losing visuals — fixed
- `collectResumeCss()` previously filtered out the `:root { --spine: ...; --ink: ...; --ink-light: ... }` rule because none of its keywords matched the regex. Without those custom properties, every `var(--spine)` in the exported PDF resolved to invalid/initial — so the bullet em-dashes lost their red color, the 22 mm spine underline under the header disappeared, and `--ink-light` fell back to inherited (often black).
- Fix: `:root` and `@media print` rules are now always included; the keyword regex was widened to cover `.cv-profile`, `.cv-languages` and `.cv-references-note`.

### Preview opens in a central tab — fixed
- `activateView()` used to call `workspace.getRightLeaf(false)`, which always opened the preview in the right sidebar.
- It now calls `workspace.getLeaf('tab')`, which opens the preview as a normal tab in the central editor area.

### Files affected
- `src/parser.ts` — Professional Profile extraction.
- `src/types.ts` — added `profile?: string` on `ResumeData`.
- `src/renderer.ts` — `phone` / `location` / `languages` rendering, `cv-profile` rendering.
- `src/previewView.ts` — `collectResumeCss` now keeps `:root` and `@media print`.
- `src/main.ts` — `activateView` uses `getLeaf('tab')`.

## 2026-10-06 17:04 — Auto-save restored, exports via data: URL

Reverts the iframe.print() approach (which produced no output at all in the user's environment) and brings back Electron `printToPDF` with one key change: the export HTML is delivered as a `data:text/html;...` URL instead of a `file://` URL. data: URLs are resolved entirely in-memory and bypass every path-related failure mode we've theorised (symlinks, `realpathSync`, `loadURL` quirks). The hidden BrowserWindow, the 800 ms layout settle, the save dialog, and the in-place write to disk are otherwise unchanged.

### Files affected
- `src/previewView.ts` — back to Electron BrowserWindow + printToPDF, with a data: URL.
- `main.js` (regenerated).

## 2026-10-06 16:32 — Blank PDF: symlink-resolved tmp path, longer timeout, dual page-break, debug dump

The user reported that exporting still produces a blank PDF even after the preview-reuse fix in the previous commit. The console line `MD2Resume export: 2 page(s) → PDF (5805 chars)` confirms 2 pages of HTML were generated and serialized, so the bug is downstream — in the file:// URL Electron receives, or in the printToPDF call, or in the page-break CSS.

Changes:

- **`fs.realpathSync` on the temp file** before loading it. On macOS, `os.tmpdir()` returns a path like `/var/folders/.../T/` which is a symlink to `/private/var/folders/.../T/`. Electron has been seen to silently load an empty page when given a symlinked `file://` URL. RealpathSync normalises the path so the URL is a single concrete file.
- **Timeout raised from 300 ms to 600 ms** before `printToPDF`. The 300 ms delay is sometimes too short for Chromium to apply the styles (especially the `:root` custom-property declaration) and complete layout.
- **Both `break-after: page` and `page-break-after: always`** on `.resume-page`. The `page-break-after` property is the legacy name; both are needed for older Electron Chromium builds where `break-after` is not recognised.
- **Diagnostic dump**: every export now also writes `md2resume-export-<ts>.html` to `os.tmpdir()` and logs its path. If the user sees a blank PDF, they can open that HTML in Chrome and confirm whether the HTML itself is correct.

### Files affected
- `src/previewView.ts` — realpathSync, 600ms timeout, dual page-break, debug dump.
- `main.js` (regenerated).

## 2026-10-06 15:15 — Profile heading restored, blank PDF export fixed

### Professional Profile heading
- `## Professional Profile` sections were previously extracted by the parser and rendered as a `<section class="cv-profile">` block with **no heading**, hiding it from the preview.
- Restored the design's small-caps `cv-section-head` heading. The parser now extracts the heading text as well. The renderer emits `<section class="cv-section cv-profile-section"><h2 class="cv-section-head">Professional Profile</h2>…</section>` so the heading is visible.
- The `cv-section` class on the same element means the existing pagination treats it as a section: it falls into the "no `cv-entry` children" path and is appended as a single block per page.
- CSS: renamed `.cv-profile` to `.cv-profile-section`. `collectResumeCss`'s regex still matches `cv-profile` as a prefix and captures the new selector.

### Blank PDF export
- Symptom: PDF export produced a file but the file showed no content. Preview worked correctly.
- Root cause: `openPrintWindow()` called `buildPagedPreview(stagingFrame, resumeHtml)` a second time after the preview's first call. Each `buildPagedPreview` constructs its own off-screen staging, runs pagination, and emits page divs into the target frame. Re-running it on the same input but in a different DOM context occasionally produced empty page divs in production (likely a layout timing race between the two calls).
- Fix: `openPrintWindow()` now reuses the preview's already-paginated page divs (`previewFrame.querySelectorAll('.resume-page')`). The preview paginates synchronously after `editor-change`, so by the time the user clicks "Export as PDF" the preview's pages are guaranteed in sync.
- Added a fallback that paginates into a detached frame only if the preview has zero pages (e.g., the view was just activated and hasn't rendered yet). A `console.warn` indicates when the fallback fires.
- Added a `console.log` reporting the page count and the serialized HTML length for diagnostics.

### Files affected
- `src/parser.ts` — profile extraction now returns `{ heading, paragraphs }`.
- `src/types.ts` — added `ResumeProfile` interface.
- `src/renderer.ts` — `renderProfile` now emits the section heading.
- `src/previewView.ts` — `openPrintWindow` reuses preview pages; adds logging.
- `styles.css` — `.cv-profile` → `.cv-profile-section`.
- `main.js` (regenerated).
