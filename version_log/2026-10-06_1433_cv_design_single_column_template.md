# 2026-10-06 14:33 — Switch to cv_design.html-inspired single-column template

## Context
The plugin previously rendered a timeline résumé with dot-leader date alignment,
3-column tag-list grids, and section rules. They provided a richer design template at
`changes/cv_design.html` (magazine-style, cream background, red spine accents,
small-caps typography) but asked for a version with no columns and no tables.
Confirmed via questions:
- Drop both the left vertical spine sidebar and the `.cv-two-col` 2-column grid.
- Keep the existing `### Title | Date` + `*subtitle*` parser unchanged.
- Skip a dedicated Languages section for now (language info remains in the frontmatter `header` line).
- Add a single italic references disclaimer line via a new frontmatter key.

## Files affected
- `src/renderer.ts` — full rewrite of the entry/section/header markup
- `src/previewView.ts` — updated pagination class selectors + `collectResumeCss` regex
- `styles.css` — full rewrite of the resume content styles to match the design palette
- `changes/cv_content.md` — added `references_note` frontmatter field
- `main.js` — regenerated by `npm run build`

## Before vs After

### Renderer (`src/renderer.ts`)
**Before** — dot-leader and three-column tag list:
```ts
parts.push(`<div class="entry-header">
    <span class="entry-title">${escHtml(entry.title)}</span>
    <span class="dot-leader"></span>
    <span class="entry-date">${escHtml(entry.date)}</span>
</div>`);
// …
parts.push(`<div class="tag-list">\n${items}\n</div>`);
return `<section class="resume-section" data-id="${escHtml(section.id)}">
    <h2 class="section-heading">${escHtml(section.heading)}</h2>
    <hr class="section-rule">
    ${parts.join('\n')}
</section>`;
```

**After** — flat design-style entry + italic meta line, flat tag list, single-line references note:
```ts
parts.push(`<div class="cv-entry-head">${escHtml(entry.title)}</div>`);
parts.push(`<div class="cv-entry-meta">${escHtml(entry.date)}</div>`);
// …
parts.push(`<div class="cv-tag-list">\n${items}\n</div>`);
return `<section class="cv-section" data-id="${escHtml(section.id)}">
    <h2 class="cv-section-head">${escHtml(section.heading)}</h2>
    ${parts.join('\n')}
</section>`;
// …and after the sections:
const referencesNoteHtml = referencesNote
    ? `<p class="cv-references-note"><em>${escHtml(referencesNote)}</em></p>`
    : '';
```

### Pagination (`src/previewView.ts`)
**Before**: queried `.resume-section`, `:scope > .entry, :scope > .tag-list`, and `:scope > hr`.
**After**: queries `.cv-section` and `:scope > .cv-entry, :scope > .cv-tag-list`. The `<hr>` lookup and cloning were removed entirely.

### Styles (`styles.css`)
- New palette: `--spine: #8B2020`, `--ink: #1C1A17`, `--ink-light: #5C5750`, page background `#F7F4EE`.
- `.resume-name` is now small-caps with `font-variant: small-caps` and `letter-spacing: 0.06em`.
- `.cv-section-head` is uppercase, tracked, and underlined with the spine color (replaces `.section-rule`).
- `.cv-tag-list` is a single-column block list (no more 3-col grid).
- Bullet items use the design's em-dash marker (–) in spine red.

### `changes/cv_content.md`
Added:
```
references_note: Additional references including Instituto Cervantes Director and Universidad de Sevilla faculty available upon request.
```

## Reasoning
- Visual fidelity to the design while honoring the "no columns, no tables" constraint.
- Keeps the parser untouched because the entry syntax in the markdown already maps cleanly onto the new `cv-entry-head` / `cv-entry-meta` structure.
- Pagination needs to know the exact class names of the section container and its entry children to split content into pages — those had to be renamed in lockstep with the renderer and styles.
- `references_note` was added as a generic frontmatter key (not section-name magic) so it works for any CV and the wording is fully user-controlled.

## Risks / side effects
- The 3-column certifications grid is gone; long certifications lists now stack vertically and may push content onto more pages. If this becomes undesirable, a flat 2-column grid (no `<table>`) could be reintroduced as a class on a specific section.
- The dot-leader date alignment is gone. Dates are now on their own italic meta line directly under the title.
- The pagination logic still greedily fills pages; with the redesigned compact headings it tends to fit more on each page, which is consistent with the design's single-page-feel layout.
- The `collectResumeCss` regex now only matches the new class names. If future styles add `.dot-leader` etc. back, the regex will need to grow.
