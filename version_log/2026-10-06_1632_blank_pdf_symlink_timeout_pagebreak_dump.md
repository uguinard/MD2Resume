# 2026-10-06 16:32 — Blank PDF: symlink-resolved tmp path, longer timeout, dual page-break, debug dump

## Context
The user reported that even after the previous "reuse preview pages" fix, exporting produces a 2-page blank PDF. The new console log `MD2Resume export: 2 page(s) → PDF (5805 chars)` confirms:
- 2 page divs were retrieved from the preview frame (so the preview itself is fine).
- 5805 chars of HTML were serialised — there's content in the export.

So the bug is downstream: in the file the BrowserWindow loads, in the page-break CSS, or in the printToPDF timing.

## Hypotheses considered

1. **macOS /var symlink** — `os.tmpdir()` returns `/var/folders/.../T/` which is a symlink to `/private/var/folders/.../T/`. Some Electron versions silently load an empty page when the path is symlinked. Fix with `fs.realpathSync`.

2. **300 ms delay too short** for Chromium to apply the `:root` custom-property rule and complete layout in some environments. Increase to 600 ms.

3. **`break-after: page` not honoured** in some Chromium builds used by older Electron. Add the legacy `page-break-after: always` as a fallback. Both properties are widely supported now but the legacy one is harmless.

4. **Debug visibility** — we have no way to inspect what the BrowserWindow actually sees. Added a dump of the export HTML to `os.tmpdir()` and a `console.log` of its path so the user can verify the HTML in Chrome themselves if the PDF is still blank.

```ts
// after
const tmpPath = path.join(os.tmpdir(), `md2resume-${Date.now()}.html`);
fs.writeFileSync(tmpPath, doc);

// Resolve any symlinks (notably /var/folders → /private/var on macOS) so
// the file:// URL that Electron loads is unambiguous. Some Electron
// builds silently hang or load an empty page when given a symlinked path.
const realTmpPath = fs.realpathSync(tmpPath);

const printWin = new remote.BrowserWindow({ show: false });
try {
    const pdfData = await new Promise<Uint8Array>((resolve, reject) => {
        printWin.webContents.on('did-finish-load', () => {
            window.setTimeout(() => {
                void printWin.webContents.printToPDF({...}).then(resolve, reject);
            }, 600);
        });
        printWin.loadURL(`file://${realTmpPath}`);
    });
```

## What the user should do next

1. Reload the plugin (Settings → Community plugins → MD2Resume → off → on).
2. Open `MD2Resume-Template.md`, click ribbon, click Export as PDF.
3. New console log will say `MD2Resume export: HTML dumped to /var/folders/.../md2resume-export-<ts>.html`. Open that file in Chrome and print to PDF manually. If the manual PDF is non-blank, the issue is in Electron; if the manual PDF is also blank, the HTML is the issue and we have a file to inspect.

## Risks / side effects
- `realpathSync` adds one syscall per export (negligible).
- Longer timeout adds up to 300 ms to the export (acceptable).
- `page-break-after` is a no-op in current Chromium but harmless.
- The debug dump leaves an HTML file in tmpdir per export. It's small (~5–10 KB) and tmpdir is cleaned by macOS, but if the user wants it gone, switch to the symlink approach for the dump file too.
